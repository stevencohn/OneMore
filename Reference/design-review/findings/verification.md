# OneMore — Verification of Top 10 findings

Date: 2026-11-23. Source: `synthesis.md` Top 10 priorities. The details for each finding are in `verification/<ID>.md`.

| ID | Title | Verdict | Evidence |
|---|---|---|---|
| TOP01 | Tests do not run as a CI gate on push/PR | Confirmed | `build.yml:3-4` runs only on `workflow_dispatch`. `run_tests` defaults to false (`:23-27`), and the test step comes after signing (`:264-267`). No other workflow runs the tests. |
| TOP02 | Settings writes are not atomic or locked, and defaults are saved after a failed read | Confirmed | `SettingsProvider.cs:40-67` turns a failed load into a minimal default. `Save()` (`:169-173`) then writes over the whole file in place, with no mutex, temp file or `.bak`. There are 116 `new SettingsProvider()` sites. |
| TOP03 | The `ProgressDialog` worker lambda has no catch (`async void` on a raw `Thread`) | Confirmed | The `try` at `ProgressDialog.cs:140` wraps only the thread's construction. An exception after the `await` (`:149`) is unhandled on the thread pool, which ends dllhost. `Close()` is never reached. Null pages from `GetPage` make this reachable. |
| TOP04 | The pipeline is outside the `ServiceLoop` stop mechanism, stages are switched off permanently, and stages have no timeout | Confirmed | `PipelineService.cs:110-139` cancels only on `ApplicationExit`, and `AddIn.cs:372-394` keeps no reference to the pipeline. After 5 failures `state.Off = true` (`:307-319`) and is never reset. |
| TOP05 | Updater: no Authenticode check, a checksum mismatch can be clicked through, the download is unsound, paths are unquoted | Confirmed | The hash comes from the same release body as the binary. `UpdateCommand.cs:94-101` offers Yes/No on `Mismatch`. There is no `EnsureSuccessStatusCode`. `File.OpenWrite` does not truncate. The `.cmd` paths are unquoted (`Updater.cs:330,343`). |
| TOP06 | Navigator reads the full all-notebooks hierarchy on each navigation and each dropdown open | Confirmed | `IsDeleted` calls `GetRecycledPageIds` → `GetHierarchy(null, hsPages)` once per settled navigation. The ribbon `getContent` blocks on the same read, and it is invalidated after every navigation. The wording needs tightening: once per navigation, not once per 1.25 s poll. |
| TOP07 | IPC boundary: no CLI allowlist, machine-global single-instance pipe, `WaitForPipeDrain` with no timeout, no framing | Confirmed | `CommandService.cs:228-240` checks only the regex before `Activator.CreateInstance`. The pipe name is the fixed CLSID, with `maxNumberOfServerInstances=1` and no check of the server's SID. `WaitForPipeDrain` (`:740`) runs while holding the write lock. The allowlist issue is same-user only, so it stays Low. |
| TOP08 | The `onemore:` trusted protocol is registered for All Office Applications | Partially | The key is written under `All Applications` (`TrustedProtocolAction.cs:32`), and `[CommandService]` commands run without confirmation. But most protocol calls act only on content already on the current page, and the attacker needs a GUID they don't have. There is no arbitrary Outlook write and no new exfiltration path. |
| TOP09 | Fail fast when OneNote is unavailable, and stop ignoring `Update` failures | Confirmed | `ApplicationFactory.cs:28-76` returns null after retries without logging it, and the null shows up later as an NRE or a hidden `false`. The `out Page` constructor blocks on `.Result` (`OneNote.cs:170-176`). The RCW leak is real but the path is narrow. Callers ignore `Update`'s `false`. |
| TOP10 | Elevated installer actions: SYSTEM DB backup on user paths, unsigned WebView2 bootstrapper | Confirmed | `CA_BackupDatabase` is deferred with `Impersonate="no"` and copies user-profile paths with no reparse-point check (`BackupDatabaseAction.cs:63-83`). It runs only on a pre-8.0 upgrade. `EdgeWebViewAction.cs:86` runs the downloaded exe as SYSTEM with no signature check. |
